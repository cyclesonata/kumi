# Ableton Live の安全性

[English](../en/LIVE_SAFETY.md) · [简体中文](../zh-CN/LIVE_SAFETY.md) · 日本語

すべての Live 操作が従う安全契約です。サーバーを実際の Set に接続する前に
お読みください。

デフォルトのアダプターは `UnavailableLiveAdapter` です: 切断状態で Live I/O
を行わず、呼び出し側メタデータ、MCP 引数、シミュレーター出力、ディスク上の
Live の存在だけでは選択できません。本番ブリッジには、明示的なループバック
設定、オーナー専用シークレット、一致するプロトコル/レジストリ、報告された
操作ケイパビリティが必要です。

## デプロイメントの信頼境界

ブリッジは Kumi が Live とつながるための Kumi 自身のアダプターです。ローカルの
ループバック限定で、オーナーが管理し、クライアントは Kumi だけです。ローカル OS
アカウントを信頼します。ブリッジのプレビューと適用を実行するのはモデルではなく
Kumi のハーネスです。モデルは変更を名前で頼み、Kumi がそれをプレビューし、
プレビューの確認を自分の手元に置いたまま適用し、アンドゥとともに HISTORY に
記録します。プロデューサーが頼りにするのはアンドゥと検証というセーフティネットで、
悪意ある MCP クライアントへの防御のためだけにあって Kumi を遅くしていた手順は
なくしました(変更は 1 リクエストです。下記参照)。ブリッジは出力安全性の申告を
人間がしたことを証明できないため、Kumi はプロデューサーが聴く・録音する・再生する
ことを頼んだときにだけそれを渡します。

## ユニバーサル変更境界

すべての変更には以下が必要です:

- 新鮮な認証済みステータスと正確にネゴシエートされた操作
- 権威あるエポックスコープの参照と状態
- 有界な入力と用途別の権限
- 該当する場合の読み取り専用プレビュー
- 正確な確認、有効期限、冪等性
- Live メインスレッドでの原子的な前提条件の再チェック
- 新鮮な事後検証
- トランザクション所有の補償/アンドゥ/クリーンアップのみ
- タイムアウト、応答喪失、外部編集、検証失敗、クリーンアップ失敗後の
  明示的な**不確定**状態

クライアントは不確定な権限を新しいプレビューやキーで置き換えてはいけません。
ホストは同じブリッジと Live エポック内で、Remote Script 台帳に対して元の
トランザクション/キー/引数のみを照合し、その後で新鮮な事後状態を検証できます。
サポートされていない属性や列挙値は、安全なデフォルトではなく利用不可の証拠です。

変更は 1 つのリクエスト(`mutate`)で Live に届きます。プレビューのあと、ホストは
その変更が照合される状態ダイジェスト(`authority.digest`)を Remote Script に
求めます。エポック、Set のトラックとシーンの構造、ソングの状態、そして変更が名指す
もの自体の状態(クリップとデバイスを含まないトラック、ノートを含まないクリップ、
デバイス自身の行)に、再生系の操作では再生状態、ロケーターの操作ではロケーター、
アレンジメントの操作では関係するトラックのアレンジメントクリップが加わります。
適用では操作、引数、トランザクションと冪等キー、そのダイジェストを送ります。
Remote Script は Live のメインスレッドの同じティックでダイジェストを計算し直し、
プレビュー以降なにも変わっていないときだけ適用します。そうでなければ
「Live state changed since the preview」で拒否し、なにも起きていません。なにかを
実行する前の拒否は必ずそう示す(「…; nothing changed」)ので、ホストはそれを
不確定ではなく未送信として記録します。同じキーでの再試行では、その拒否が示すのは
その再試行が実行されなかったことだけです。最初の試行は実行されたかもしれないので、
変更は不確定のままです。Live になにかを送る前に確認で止まった取り消しは、変更を
適用済みのまま残し、次の取り消しがもう一度確認します。ブリッジは TCP 再接続をまたいで有界な実行結果
台帳を保持し、失われた応答はリプレイではなく冪等キーで正確に照合します。可聴起動、
キャプチャ開始、録音、リアルタイムアームの契約は、ブリッジ側でも出力安全性の証拠を
再検証します。(以前の 3 段階の権限、読み取り専用の `authority.preflight`、
`authority.prepare` によるワンタイム確認、そして実行は、それを使うテストのために
残っています。)

削除は明示的です。Kumi のトランザクションが作ったものではないもの(クリップ、
アレンジメントクリップ、シーン、トラック、ロケーター、デバイス、リターン)の削除には
`explicitDeletion: true` と、対象とその置き場所の正確な同一性フェンスが必要です。
取り戻せるのは Live 自身のアンドゥだけなので、HISTORY はその削除を残します。
トランザクションが作ったもののアンドゥはそのトランザクション自身のもので、それが
残した内容をフェンスにします。プロデューサーがその後に変えていればアンドゥは拒否されます。

プランは Live 自身のアンドゥでも 1 ステップです。Kumi はプランの最初の変更の前に
ステップを開き、最後の変更のあとに閉じます。開いたステップは Remote Script のもので、
接続が切れたとき、時間切れ、再接続時、終了時に閉じるため、Live にステップが開いたまま
残ることはありません。Live 自身のアンドゥとリドゥ(`song.undo`、`song.redo`)は
プロデューサーが Live で行ったことのためだけに使い、Kumi のアンドゥとしては使いません。

読み取りは大きさではなく作業量で区切られます。ディスカバリーのページやウィンドウ付き
スナップショットは Live のスレッドで 30 ミリ秒の予算を使い切ると止まり、続きの場所を
示します(`truncated`、`nextCursor`)。Set がどれだけ大きくても、Live の UI を
ふさぐリクエストはありません。

Kumi の Live エクステンション(Live 12.4 の Extensions SDK)は 2 つ目のチャンネルです。
ブリッジは 127.0.0.1 で、エクステンションが自分のデータフォルダーにオーナー専用で
書き込んだシークレットを使ってそれにつながります。すべてのリクエストは署名され、
レジストリで検証され、期限を過ぎれば拒否されます。その変更は Live が許す範囲で
Remote Script を通じて検証・アンドゥされ(書き込んだアレンジメントクリップは内容を
フェンスにして削除)、そうでなければ残ります。Live はエクステンションを Node の
パーミッションモデルで動かすため、自分のフォルダーしか読み書きできません。

## 実装済みの変更クラス

ガード付きワークフローは、トランスポート、クリップ起動と正確な停止、
MIDI クリップとノート、Arrangement クリップとロケーター、ミキサーと
ルーティング、Session オートメーション、デバイスと Browser ロード、
Session/Arrangement 録音、プロジェクトバックアップ、リアルタイム制御、
同意ベースのオーディオキャプチャをカバーします。それぞれに、対応する
ユーザー/運用ドキュメントでより狭いチェックがあります。

- Session 構造の作成は正確なオブジェクト ID を返します。補償とアンドゥは
  それらの ID を再チェックし、古いプロキシや再利用されたパスを削除する
  のではなく、Live のインデックス付き削除 API を呼び出します。
- `live_undo` はトランザクション固有であり、変更されたエポックや事後状態を
  拒否します。
- デバイスや Arrangement クリップの恣意削除は利用できません。クリーンアップ
  には、正確なトランザクション作成のオブジェクト ID、階層、作成時フィンガー
  プリントが必要で、変更または置換されたオブジェクトを拒否します。
- デバイス挿入と Browser ロードは空の正確なデバイスオーナーを必要とし、
  クリーンアップは作成されたデバイスが唯一の兄弟であることを要求するため、
  インデックス付き削除が無関係な兄弟を選択することはありません。
- 移動は破壊的なクリーンアップ権限を発行しません: 既存のクリップは移動後も
  既存のままで、ソースとデスティネーションのコンテンツフィンガープリントは
  フェンスされ、回復は正確な不変の逆移動トランザクションのみを使用します。
  トランザクション作成のクリップを移動すると、以前のクリーンアップトークンが
  原子的に消費され、移動結果の削除権限は発行されません。
- MIDI キャプチャはすべての Session スロットが空の場合にのみ通知されるため、
  部分的に失敗する Capture MIDI 実装が、正確な復元パスなしに既存のクリップ
  コンテンツを変更することはありません。

読み取り専用操作には、ステータス、ケイパビリティネゴシエーション、スナップ
ショット、ディスカバリ、プレビュー、プロジェクト検査、サブスクリプション読み
取り、リアルタイム統計、呼び出し側 PCM 解析/リファレンス比較、呼び出し側
宣言の Live コンテキスト診断が含まれます。読み取り専用ツールは再生や録音を
開始しません。

セマンティック Set ページは明示的な許可リストから構築され、Live 参照/オブジェクト
ID、エポック/リビジョン、確認、トークン、トランザクション、冪等性、secret、MAC、
復旧権限を除外します。どのプライバシープロファイルも絶対パスを出力しません。
スナップショット ID とページカーソルは説明用座標であり、クロスラン ID や変更権限
ではありません。オフライン差分は一意なセマンティック証拠だけを使い、曖昧性と
切り詰め制限を保持し、常に `mergeProposed=false` を報告します。`.als` を編集せず、
不透明なプラグイン/Max 状態を可搬とは扱いません。

## インポートメディアのステージング

オーディオインポート（`live_audio_import_*`）と Simpler サンプル置換
（`live_simpler_*`）は、認可されたソースファイルの検証済み読み取り専用コピーを、
永続的で所有者管理のディレクトリにステージします: Linux/macOS では
`~/.config/ableton-mcp/import-staging`、Windows では
`%APPDATA%\ableton-mcp\import-staging`（絶対パスである必要がある環境変数
`ABLETON_MCP_IMPORT_STAGING_DIR` で上書き可能）。ディレクトリは所有者専用
（`0o700`）で作成され、使用前に所有権が検証されます。ステージされたファイルは
書き込み不可で作成され、Live に渡されるのはそのバイトだけなので、許可ソース
ディレクトリ内のリネーム差し替えで未認可の内容をすり替えることはできません。

Live はインポートされたオーディオをその場所で参照します: apply が成功した後、
ステージコピーは作成されたクリップや Simpler のメディアそのものであり、ユーザーが
プロジェクトにファイルを集約するかクリップを削除するまで、管理ディレクトリに保持
されます。したがってステージコピーは、消費者のいないパス — プレビュー失敗、
トランザクション期限切れ、立ち退きまたは復旧確定、ディスパッチ前の apply 拒否、
apply 失敗、undo（作成クリップの削除または元サンプルの復元後）— でのみ解放され、
apply 成功時、ホスト終了時、経過時間では解放されません。参照するクリップがなくなった
後であれば、運用者が管理ディレクトリを手動で整理できます。

## 可聴な Session アクション

シーン/クリップの起動には、明示的な出力安全性の証拠、正確な適格ターゲット、
停止した非録音のベースライン、安全なモニタリング/arm 状態、新鮮な再生
リビジョン、有界な起動量子化、プレビューでキャプチャされ Live のスレッドに
引き継がれ再チェックされるトラック/シーン/スロット/クリップ ID が必要です。
所有停止はプリフライトされたターゲットのみをクリアします。
`live_session_emergency_stop` は独立して、正確な新鮮なアクティブターゲット
キーと録音状態を必要とし、Session クリップ、トランスポート、Session Record、
Arrangement Record を原子的にクリアし、ホスト再起動後も存続します。

## 録音権限

録音開始プレビューには、明示的な意図、出力安全性の証拠、いずれかのレーンの
正確な armed デスティネーションが必要です。適用は、正確な以前の
Session/Arrangement 録音ブール値、デスティネーション ID、出力安全性の証拠を
マッパーに持ち込み、録音状態が変わる前に Live の変更スレッドですべて再
チェックされます。応答喪失は不確定であり、盲目リプレイされることはありません。
停止は同じフェンスされた操作を使用し、独立した緊急停止は両方のモードを
クリアします。

## リアルタイム権限

設定された UDP ポートは常設の権限を付与しません。`realtime.arm` は、
エンドポイント、トークン、1〜30 秒の TTL、チャンネルセット、オプションの
送信元ポート、正確な公開パラメータ参照を選択します。Live はトークンを付与
する前と、キューされたすべての書き込みの前に、正確なパラメータ/オーナー/
トラック/兄弟 ID を原子的に比較するため、走査インデックスの置換や再親付けは
権限を取り消します。パケットは 512 バイト、64/s、バースト 16 に制限されます。
*受理*は*適用*を意味しません。Disarm はキューされた作業を世代フェンスします。
[REALTIME_CONTROL.md](REALTIME_CONTROL.md) を参照してください。

## オーディオ解析とキャプチャ

公開解析は正規化された PCM のみを受け付け、パスや URL は受け付けず、有界な
集約のみを返します。使い捨てのシークレット除去ワーカーで実行され、ワーカーを
強制終了してキャンセルできます。呼び出し側 PCM が Live に帰属することは、
関係が明示的に宣言されない限りなく、宣言されても未検証のままです。

Live キャプチャは別個の実 Live 専用ケイパビリティです。プレビューには、正確な
ソースクリップスロットと別の空のオーディオスロット、保存された使い捨て Set、
停止/非録音/非 armed/非入力モニター状態、復元可能なルート、1〜9 秒の長さ、
明示的な `ephemeral-analysis-and-delete` 同意、出力安全性が必要です。10 秒の
マッパーウォッチドッグ、スロット/トラック/トランスポート停止、ブリッジ
シャットダウンフック、MCP キャンセル回復、独立した再起動後緊急ツールが録音
権限を拘束します。クリーンアップは正確な所有クリップのみを削除し、プライベート
隔離後に検証済みの WAV/ASD をアンリンクします。恣意削除やフォレンジック消去の
主張はしません。[AUDIO_INTELLIGENCE.md](AUDIO_INTELLIGENCE.md) を参照してください。

## ブリッジの安全性

ブリッジは数値ループバックのみです。リクエストとレスポンスは、正規の
HMAC-SHA256、チャレンジ/ブリッジエポックバインディング、正のシーケンスと
リプレイチェック、有界なフレーム/コレクション、デッドラインを使用します。
ソケットワーカーは Live オブジェクトに触れません。スケジュールされた
Control Surface コールバックがメインスレッドで Live 作業をドレインします。
再接続は新しい参照エポックを作成します。シャットダウンは、サブスクリプション、
リスナー、クライアント、ワーカー、キューされたコールバック、リアルタイム権限、
参照を解放します。アクティブなキャプチャについては、正確な停止/復元を再主張
しますが、Remote Script は PCM をアンリンクできないため、唯一の回復 ID を破壊
する代わりに、所有クリップ/パスを可視の回復残留物として保持します。

## 実 Live エビデンスの境界

Fake-Live、シミュレーター、パッケージ、プロパティ、ベンチマークの結果は、
制御された契約を証明するものであり、Live の動作ではありません。追跡された
エビデンスは、macOS Live 12.4.5b8 での Phase 8 までのインストール済み実 Live
観測を別途記録しており、通常のクリーンアップと障害回復を含みます。Windows Live
の動作、ハードウェア出力の安全性、アクセシビリティ、署名、公証を証明するもの
ではありません。

可視の Live 状態が認証済みステータスや新鮮なディスカバリと矛盾する場合は、
クライアントを停止し、秘匿されたエビデンスを保持し、所有する可聴ライフサイクル
がアクティブな場合は独立した緊急回復を使用し、その不一致を欠陥として扱って
ください。
